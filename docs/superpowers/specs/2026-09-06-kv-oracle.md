# KV Oracle 容量收益诊断

用户已批准实现、推送现有 `repro/fluxmoe` 分支和服务器实验交接。本轮只实现已讨论的容量诊断与继续/停止判断；不优化或替换专家缓存、卸载、路由或 CUDA 内核。

## 实验合同

同一已有 Qwen3-Next-80B-A3B-Instruct、原始 BF16、4 张独占 H100、TP4、eager/编译 level=0、禁用 prefix caching、固定输入与输出 token 数。使用已提交 ShareGPT 数据，不需要校准或下载。保持旧 partial-host/expert-cache 实验及服务器新增失败证据导出逻辑。

- `r0`：全 GPU resident，0.60 自动 KV，得到各 rank 真实 KV K0。
- `small`：仍为全 GPU resident，显式 KV 目标为 K0+3,200,000,000 bytes/卡。
- `large`：仍为全 GPU resident，显式 KV 目标为 K0+18,100,000,000 bytes/卡。
- K0 来自当前相同负载的完整 r0 实验实际分配，不用 profiling available 字段，也不硬编码旧报告的 9 GB。只有各 rank K0 一致时使用单个 override。实际 KV blocks/bytes 必须记录并验证增量；block 对齐不等于精确申请字节。
- O 组显式 KV 会绕过 utilization 自动预算，允许超出 0.60，但始终标记 `diagnostic_only=true`、`comparison_backend=kv-oracle`、`formal_offload_gain=false`。这是乐观容量参考，不是严格数学上界或公平卸载比较。
- 普通 resident 的显式 KV 覆盖限制和正式 R/B/C 校验不能放宽。Oracle 专用 backend 才能覆盖显式 KV；正式 analyzer 显式拒绝 Oracle 数据。报告显示 nominal R budget 与实际占用，不把 O 的 0.60 参数显示为已遵守该限制。

## 有限工作负载与顺序

预设 `control`=32 requests/4096 input/64 output；`main`=512/4096/256；`long`=512/4096/1024。均请求 max_num_seqs=512（实际受 requests 数及 KV 限制）、max_num_batched_tokens=8192、seed=20260905。固定同一输入哈希，重复输入数如实记录。

`screen`：单个预设、1 warmup+1 repetition，r0→small→large。默认 main，control 用独立 suite ID；long 只在需要时手动追加。

`confirm`：单个选中预设、1 warmup+3 repetitions。支持 forward 顺序 r0→small→large；reverse 顺序 large→small→r0 需提供此前相同配置/模型/输入/SHA 的 r0 anchor，仅借用 K0。reverse 中新的 r0 必须与 anchor 实际 K0 相同，否则该组不可确认。anchor 的测量轮数可与 confirm 不同，但不可把其吞吐替代新 r0。拒绝不相干 anchor 和其他 Oracle 作为 anchor。

每一点是新进程/容器。失败、OOM、超时或安全拒绝都保存当前状态和已完成轮次，不自动缩小 KV/工作负载伪装为同一实验；停止后续点并导出失败。单轮只能用于筛查，不给稳定结论。

## 显存安全与观测

默认安全 fraction=0.90、额外 margin=2,000,000,000 bytes/卡。以 r0 实际 GPU/current/peak 数据估算非 KV 开销，再加目标 KV 和 margin；过预算时拒绝启动 O。初始化后、每轮结束再验证实际边界和 Torch peak。此检查是保守估算/边界验证，不是硬件强制显存隔离；不能声称捕获全部瞬态非 Torch 峰值。只允许显式改变安全参数后用新 ID 重跑。

增加原生路径轻量 worker probe：通过实际 root model forward hook 统计模型前向调用数；能从 pinned model_runner 读取 input_batch.num_reqs 时，记录该字段的观察次数、平均及峰值，明确它不是等待队列长度。不能用提交请求数或 token rows 冒充实际请求并发。未知 KV occupancy/preemption 指标记为 unavailable，不猜测。不得复制路由 IDs 到 CPU 或做每层 GPU synchronize 来采集这些指标。

计时前在 GPU 同步后启用/reset probe 和 allocator peaks，计时后同步、停止 probe、读取数值；排除初始化和 warmup。模型/路由不改变，运行期不做专家权重加载。固定输出 token 数、端到端秒数、per-rank KV/current/peak、原生参数驻留检查、计数可用性、smoke、输出哈希、版本和执行 SHA 均可追溯。

## 决策和证据边界

独立 analyzer 验证完整三组、同配置/输入/软件/硬件、实际 KV 增量、固定 tokens/seconds、每轮证据覆盖和 smoke。缺证据/安全失败不等于没有收益。跨 repetition 报告中位数和范围，confirm 至少三轮且范围不重叠才描述为可重复信号；反序组用于复查顺序影响。

建议工程止损线（非统计学定理）：重复确认的 small/large 均低于10%且没有调度机制改善 → 停止该负载的吞吐路线；10–20% → 仅低成本改动；small 至少20%且前向次数减少或有效请求批次增长 → 考虑后续小比例卸载；只有 large 有信号 → 不能据此证明5层/1槽可行。记录每轮 r0 与 O 的耗时差作为对应 KV 的时间收益空间，不用 B 的不同调度开销直接外推 C。所有输出始终 `formal_offload_gain=false`。
